# งานที่ต้องทำเพิ่ม (S365 Fitness)

รายการระบบที่เจ้าของขอและจุดที่ต้องแก้ เรียงตามลำดับที่ควรทำ ห้องไหนรับงานต่อให้อ่านไฟล์นี้ก่อน
และอัปเดตสถานะเมื่อทำเสร็จ

## 1. ลูกค้าเช็กอินเองด้วยการสแกน แพ็กเกจ โปรโมชั่น ตารางเทรนเนอร์ (เจ้าของขอ 27 พ.ย. 2026)

สถานะ: สร้างแล้วในกิ่ง `claude/pensive-curie-omuh57` ยังไม่ขึ้นเว็บจริง ต้องรัน `supabase/memberships.sql` ใน Supabase ก่อนใช้
ส่วน LINE ยังไม่ได้ทำ (ดูด้านล่าง) วิธีใช้อยู่ใน README หัวข้อ "แพ็กเกจ วันหมดอายุ เช็กอินด้วยการสแกน และตารางเทรนเนอร์"

### สิ่งที่เจ้าของตัดสินใจแล้ว

- ลูกค้าต้องลงทะเบียนกับยิมก่อน ระบุตัวด้วยเบอร์โทรหรือ LINE และอยากให้สแกนใน LINE แล้วมีแจ้งเตือนเด้งใน LINE
- "เวลาที่จะหมด" คือวันหมดอายุสมาชิก และชั่วโมง PT ที่ซื้อไว้
- เจ้าของจะสร้างแพ็กเกจเองในหลังบ้าน เพราะแต่ละรอบโปรโมชั่นไม่เหมือนกัน พนักงานเลือกว่าลูกค้าซื้อแพ็กเกจไหน
- โปรโมชั่นแสดงกับคนที่จะหมดอายุภายใน 1 สัปดาห์ หรือคนที่ชั่วโมง PT ใกล้หมด เพื่อชวนซื้อซ้ำ
- ไม่มีเช็กเอาต์ ถือว่าอยู่ราว 1 ถึง 1.5 ชั่วโมง
- เทรนเนอร์ลงตารางงานของตัวเองทุกเช้า ผู้จัดการต้องเห็นว่าใครว่างช่วงไหน

### ค่าที่ห้องนี้เลือกให้ก่อน เจ้าของเปลี่ยนได้

- สมาชิกที่หมดอายุแล้วยังสแกนเช็กอินได้ แต่หน้าจอลูกค้าและรายการของพนักงานจะขึ้นเตือนว่าหมดอายุ
- สแกนซ้ำภายใน 3 ชั่วโมงไม่นับเป็นการเข้าใหม่
- "PT ใกล้หมด" คือเหลือไม่เกิน 2 ชั่วโมง ตั้งค่าได้ในแต่ละโปรโมชั่น
- ตารางเทรนเนอร์แบ่งรายชั่วโมง 06:00 ถึง 22:00

### ยังไม่ได้ทำ: LINE

ต้องให้เจ้าของเตรียมก่อน แล้วส่งค่ามาทางหน้าตั้งค่า Environment Variables ของ Vercel (ห้ามพิมพ์ค่าลับในแชต):

1. LINE Official Account ของยิม (มีอยู่แล้วคือ @s365fitness ต้องยืนยันว่าเป็นบัญชีแบบ Official Account)
2. เปิด Messaging API ของบัญชีนั้นใน LINE Developers แล้วออก Channel access token
3. สร้าง LINE Login channel และ LIFF app ที่ชี้มาที่ `/checkin`

งานฝั่งโค้ดที่ต้องทำต่อ: ให้หน้า `/checkin` เปิดใน LINE แล้วจำ LINE ของลูกค้า (คอลัมน์ `members.line_user_id` เตรียมไว้แล้ว)
ผูกครั้งแรกด้วยเบอร์โทร ครั้งต่อไปกดเช็กอินได้เลย และส่งข้อความยืนยันกับเตือนใกล้หมดอายุทาง LINE
การส่งข้อความหาลูกค้าทาง LINE ต้องถามเจ้าของก่อนเปิดใช้ทุกครั้ง และข้อความแบบ push มีโควตาฟรีจำกัดต่อเดือน

### ยังไม่ได้ทำ: อื่นๆ

- นำข้อมูลลูกค้าจาก Excel เข้าระบบ (หัวข้อ 5)
- ป้าย QR ที่เปลี่ยนรหัสเองทุกวัน ตอนนี้เจ้าของกดสร้างรหัสใหม่เองได้
- คัดลอกตารางเทรนเนอร์จากวันก่อนหน้า

## 5. ข้อมูลลูกค้าเดิมใน Excel (เจ้าของส่งให้ดู 27 พ.ย. 2026)

สถานะ: แยกข้อมูลเป็นตารางสะอาดแล้ว ยังไม่นำเข้าระบบ เจ้าของสั่งให้รอก่อน

ไฟล์ Excel ของยิมและไฟล์ที่แยกแล้วมีข้อมูลส่วนบุคคลของลูกค้า ห้ามเก็บใน repo นี้ (repo เป็นสาธารณะ)
ไฟล์ที่แยกแล้วส่งให้เจ้าของเก็บไว้เอง ถ้าต้องใช้อีกให้ขอไฟล์จากเจ้าของ

โครงสร้างไฟล์เดิม (41 แผ่นงาน):

- แผ่นรายเดือน ชื่อแบบ `MM-YY` ตั้งแต่ 12-23: ยอดขายรายวันของผู้ขายแต่ละคน แบ่งหมวด New Member, Renew Member, New PT, Renew PT
- `member month`: สมาชิกรายเดือน รหัส `SM....` มีชื่อ เบอร์โทร แพ็กเกจ ยอดชำระ วิธีชำระ ผู้ขาย วันที่ซื้อ วันเริ่ม วันหมดอายุ
  และช่องต่อท้ายไม่มีหัวข้อที่ใช้จดการต่ออายุ การพัก (hold/drop) และวันหมดอายุใหม่
- `member year`: สมาชิกรายปี รหัส `SY....` โครงเดียวกัน
- `Up-member year 1`: การอัปเกรดและต่ออายุเป็นรายปี
- `Course PT`: คอร์ส PT รหัส `PT....` มีจำนวนครั้งที่ซื้อ (เช่น 12 หรือ 12+2) แต่ไม่มีจำนวนครั้งที่ใช้ไปหรือคงเหลือ
- `Master (ห้ามลบ)`: แม่แบบของแผ่นรายเดือน

สิ่งที่ต้องรู้ตอนนำเข้า:

- วันที่ปนกันหลายรูปแบบ: วันที่จริงของ Excel ข้อความแบบ `05.01.24` และปี พ.ศ.
- เบอร์โทรบางแถวเลข 0 ข้างหน้าหาย เพราะ Excel เก็บเป็นตัวเลข
- ลูกค้าคนเดียวมีหลายแถว (ซื้อหลายครั้ง) และสะกดชื่อต่างกันได้ ใช้เบอร์โทรจับคู่จะแม่นกว่าชื่อ
- แพ็กเกจจริงที่พบ: รายเดือน 1, 2, 3, 3+1, 6, 6+1 เดือน และมีแถมเป็นวัน รายปี 1 ปี และ 1 ปีแถม 1 ถึง 3 เดือน
  คอร์ส PT ส่วนใหญ่ 12, 24, 36, 50 ครั้ง และมีแถมครั้ง
- ระบบหลังบ้านต้องรองรับ: วันเริ่มและวันหมดอายุ การแถมเวลา การพักสมาชิก การต่ออายุหลายรอบ ผู้ขายต่อรายการ และวิธีชำระ

คำถามที่ยังต้องถามเจ้าของ: ตัวย่อ RN และ P ในช่อง N/R หมายถึงอะไร, คอลัมน์ J ของแผ่น Course PT (ตัวเลข 1 ถึง 5 ไม่มีหัวข้อ) คืออะไร,
ตัวเลขในช่อง Membership ของแผ่น Up-member year 1 มีหน่วยเป็นอะไร, และจำนวนครั้ง PT ที่ใช้ไปจดไว้ที่ไหน
