# S365 Fitness — ระบบบริหารจัดการฟิตเนส

Next.js 16 (App Router) + Supabase (Postgres, Auth, RLS) ระบบจัดการฟิตเนสสำหรับ S365
แยกสิทธิ์การใช้งานเป็น 3 กลุ่ม: **เจ้าของ/พนักงาน**, **เทรนเนอร์**, **ลูกค้า** โดยแต่ละกลุ่มมีหน้าจอ
ของตัวเองและมองไม่เห็นฟีเจอร์ของกลุ่มอื่น (บังคับด้วย Row Level Security ที่ตัวฐานข้อมูล ไม่ใช่แค่ที่ UI)

## โครงสร้างโปรเจกต์

```
supabase/schema.sql       ตาราง + RLS policies + trigger ทั้งหมด (รันครั้งเดียวตอนตั้งโปรเจกต์)
supabase/website-cms.sql  ตารางและที่เก็บภาพของหน้าเว็บ สำหรับระบบแก้เว็บจากหลังบ้าน (รันต่อจาก schema.sql)
supabase/memberships.sql  แพ็กเกจ การซื้อ วันหมดอายุ โปรโมชั่น เช็กอินด้วยการสแกน และตารางเทรนเนอร์ (รันต่อจาก schema.sql)
src/app/page.tsx          หน้าเว็บสาธารณะ (ไม่ต้องล็อกอิน) ประกอบจากคอมโพเนนต์ใน src/components/site
src/app/owner/website     หน้าหลังบ้าน "เว็บไซต์": แก้ข้อความ อัปโหลด จัดลำดับ ซ่อน และลบภาพของหน้าเว็บ (เฉพาะเจ้าของ)
src/content/site-texts.ts รายการข้อความทุกช่องที่แก้จากหลังบ้านได้ พร้อมค่าเริ่มต้นภาษาไทยและอังกฤษ
src/content/ui-strings.ts  คำบนปุ่มและเมนูของหน้าเว็บ ทั้งสองภาษา
src/app/en/page.tsx       หน้าเว็บภาษาอังกฤษ (ใช้คอมโพเนนต์ชุดเดียวกับหน้าไทย)
src/app/tools, guides     เครื่องมือและคู่มือสำหรับผู้เข้าชม: BMI, แผนออกกำลังกาย, แผนการกิน, ท่าที่บ้าน, ท่ายืด (มีคู่ภาษาอังกฤษใต้ src/app/en)
src/content/tools.ts      รายการเครื่องมือและข้อความหัวหน้าแต่ละหน้า
src/content/guides.ts     เนื้อหาท่าออกกำลังกายที่บ้านและท่ายืด ทั้งสองภาษา
src/content/media.ts      ภาพชุดเดิมที่มากับเว็บ ใช้เมื่อหมวดนั้นยังไม่มีภาพที่อัปโหลด
src/lib/site-content.ts   รวมค่าเริ่มต้นกับสิ่งที่แก้จากหลังบ้าน แล้วส่งให้หน้าเว็บ
src/assets/site/**        ไฟล์ภาพชุดเดิมที่ย่อขนาดสำหรับเว็บแล้ว (เทรนเนอร์, ยิม, คอมมูนิตี้, ผลลัพธ์)
src/app/login             หน้าล็อกอิน (ใช้ร่วมกันทั้ง 3 กลุ่ม แล้ว redirect ตาม role)
src/app/owner/**          แดชบอร์ดเจ้าของ/พนักงาน (ภาพรวม, สมาชิก, ตารางคลาส, เช็คอิน, PT, การเงิน, รายงาน, ทีมงาน)
src/app/trainer/**        พอร์ทัลเทรนเนอร์ (ตารางของฉัน, บันทึกเซสชัน PT — ปุ่ม "บันทึก" เท่านั้น)
src/app/member/**         พอร์ทัลลูกค้า (ภาพรวม, จองคลาส, ยืนยัน/ปฏิเสธเซสชัน PT, การเงิน)
src/lib/supabase/*        Supabase client สำหรับ browser / server / proxy / admin (service role)
src/lib/actions/*         Server Actions ที่ทำการเปลี่ยนแปลงข้อมูลทั้งหมด (ตรวจ role ซ้ำอีกชั้นนอกจาก RLS)
src/proxy.ts              บังคับล็อกอินสำหรับ /login, /owner, /trainer, /member + กันไม่ให้ข้ามไปหน้าของ role อื่น
```

### แก้ข้อมูลบนหน้าเว็บสาธารณะ

แก้ได้เองจากหลังบ้าน ไม่ต้องแตะโค้ด: ล็อกอินด้วยบัญชีเจ้าของ แล้วเข้าเมนู **เว็บไซต์** (`/owner/website`)

- **สองภาษา**: หน้าไทยอยู่ที่ `/` หน้าอังกฤษอยู่ที่ `/en` สลับได้จากปุ่ม TH / EN บนเมนู ในแท็บข้อความเลือกได้ว่าจะแก้ภาษาไหน
  เบอร์โทร LINE ลิงก์ และตำแหน่งแผนที่ใช้ค่าเดียวกันทั้งสองภาษา (แก้ที่ภาษาไทย) ถ้ายังไม่แก้ภาษาอังกฤษ ระบบใช้คำแปลตั้งต้นในโค้ด
- **แท็บข้อความ**: พาดหัว คำอธิบายแต่ละส่วน ชื่อและคำอธิบายโซน ที่อยู่ เวลาเปิดปิด ลิงก์แผนที่ เบอร์โทร LINE และ Facebook
  ช่องที่แก้แล้วจะมีป้าย "แก้ไขแล้ว" และมีปุ่ม "คืนค่าเดิม" กดบันทึกแล้วหน้าเว็บเปลี่ยนทันที
  ปุ่มแอดไลน์และคิวอาร์โค้ดสร้างจาก LINE ID ให้เอง
- **แท็บภาพ**: อัปโหลดภาพ 5 หมวด (หน้าแรก เทรนเนอร์ โซนในยิม ผลลัพธ์ คอมมูนิตี้) ระบบย่อภาพในเครื่องก่อนส่ง
  จึงอัปโหลดภาพจากกล้องหรือมือถือได้เลย จัดลำดับ ซ่อน หรือลบทีละภาพได้
  หมวดที่ยังไม่มีภาพอัปโหลดจะใช้ภาพชุดเดิมที่มากับเว็บ และมีปุ่มคัดลอกภาพชุดเดิมเข้ามาเพื่อแก้ทีละภาพ
- **ตารางคลาสประจำสัปดาห์** (อยู่ในแท็บภาพ): อัปโหลดภาพตารางคลาสแบบเดียวกับที่โพสต์ใน Facebook หน้ายิมของเว็บจะแสดงภาพที่อัปโหลดล่าสุด
  พร้อมวันที่อัปเดต ต้องรันไฟล์ `supabase/website-cms.sql` อีกครั้งก่อนใช้ครั้งแรก เพื่อเพิ่มหมวดภาพนี้ในฐานข้อมูล
- **แท็บคลิป**: ใส่ลิงก์คลิปจาก Facebook หรือ TikTok พร้อมไฟล์คลิปสั้นหรือภาพปก หน้าแรกจะเล่นวนเฉพาะ 4 วินาทีแรกแบบไม่มีเสียง
  กดแล้วเปิดคลิปเต็มที่ต้นทาง หน้ารวมคลิปอยู่ที่ `/videos`
- **แท็บวิธีเล่นเครื่อง**: เพิ่มเครื่องทีละเครื่อง (ชื่อ โซน กล้ามเนื้อ ขั้นตอน ข้อควรระวัง ภาพ คลิป) แต่ละเครื่องมีหน้าของตัวเองที่
  `/machines/ชื่อเครื่อง` กดปุ่ม "พิมพ์ป้าย QR" เพื่อพิมพ์ป้ายไปติดที่เครื่อง ที่อยู่ของหน้าไม่เปลี่ยนแม้แก้ชื่อภายหลัง ป้ายเดิมจึงใช้ได้ตลอด
- **แท็บบทความ**: เขียนบทความที่ `/articles` เว้นหนึ่งบรรทัดเพื่อขึ้นย่อหน้าใหม่ ขึ้นต้นบรรทัดด้วย `## ` เป็นหัวข้อย่อย และ `- ` เป็นรายการ
  บทความที่ไม่มีชื่อภาษาอังกฤษจะไม่แสดงในหน้าภาษาอังกฤษ
- **แท็บสินค้า**: รายการสินค้าที่ `/shop` ปุ่มสั่งซื้อพาไปไลน์ของยิม หรือไปลิงก์ร้านที่ใส่ไว้ของสินค้านั้น
- **เมนูบนหัวเว็บ**: ยิม เทรนเนอร์ ผลลัพธ์ เครื่องมือ ติดต่อ มีหน้าของตัวเอง ส่วน คลิป บทความ ร้านค้า จะขึ้นในเมนูเมื่อมีรายการอย่างน้อย 1 รายการ
- **ตอนนี้คนเยอะไหม** (`/tools/crowd`): นับจากการเช็กอินในระบบ แสดงเฉพาะจำนวนรวม ไม่เปิดเผยข้อมูลสมาชิก
  ระดับ คนน้อย ปานกลาง คนเยอะ เทียบกับช่วงที่คนเยอะที่สุดของยิมใน 4 สัปดาห์ล่าสุด และจะแสดงเมื่อมีข้อมูลอย่างน้อย 7 วัน
- **ต้องทำครั้งแรก และทุกครั้งที่ไฟล์นี้มีการแก้**: เปิด Supabase → SQL Editor แล้วรันไฟล์ `supabase/website-cms.sql` (รันซ้ำได้ ข้อมูลเดิมไม่หาย)
  (สร้างตาราง `site_texts`, `site_photos`, `site_items` ที่เก็บไฟล์ `site-media` และฟังก์ชัน `gym_crowd`) ถ้ายังไม่รัน หน้า "เว็บไซต์" จะขึ้นข้อความเตือน
  และหน้าเว็บจะแสดงค่าเริ่มต้นตามปกติ
- **สิทธิ์**: ทุกคนอ่านเนื้อหาหน้าเว็บได้ แต่แก้ได้เฉพาะบัญชี role `owner` (บังคับที่ฐานข้อมูลด้วย RLS)
- **ภาพตัวอย่างตอนแชร์ลิงก์** (LINE/Facebook): บน Vercel ใช้โดเมน production ให้อัตโนมัติ ถ้า host ที่อื่นให้ตั้ง
  environment variable `NEXT_PUBLIC_SITE_URL` เป็นโดเมนจริง เช่น `https://your-domain.com`
- **ค่าเริ่มต้นในโค้ด**: ข้อความอยู่ที่ `src/content/site-texts.ts` ภาพอยู่ที่ `src/content/media.ts`


## ตั้งค่า Supabase

1. สร้างโปรเจกต์ใหม่ที่ [supabase.com](https://supabase.com) (เลือก region ใกล้ผู้ใช้งาน เช่น Singapore)
2. เปิด **SQL Editor → New query** วางเนื้อหาทั้งหมดจากไฟล์ [`supabase/schema.sql`](./supabase/schema.sql) แล้วกด Run
   - สร้างตาราง, ฟังก์ชัน, trigger และ RLS policy ทั้งหมดในคำสั่งเดียว ปลอดภัยที่จะรันซ้ำ (ใช้ `if not exists` / `or replace`)
3. ไปที่ **Authentication → Emails** เพื่อปรับข้อความอีเมลเชิญ (Invite user) ให้เป็นภาษาไทยได้ตามต้องการ
   (ระบบใช้ฟีเจอร์ "Invite" ของ Supabase Auth ในการสร้างบัญชีพนักงาน/เทรนเนอร์/ลูกค้า — ผู้ใช้จะได้อีเมลให้ตั้งรหัสผ่านเอง)
4. ไปที่ **Authentication → URL Configuration** ตั้งค่า:
   - **Site URL**: โดเมนจริงตอน deploy (เช่น `https://s365.vercel.app`)
   - **Redirect URLs**: เพิ่ม `http://localhost:3000/**` (ตอน dev) และโดเมน production `https://your-domain.com/**`
5. คัดลอกค่าจาก **Project Settings → API**:
   - `Project URL` → `NEXT_PUBLIC_SUPABASE_URL`
   - `anon public` key → `NEXT_PUBLIC_SUPABASE_ANON_KEY`
   - `service_role` key → `SUPABASE_SERVICE_ROLE_KEY` (⚠️ ห้ามใช้ค่านี้ฝั่ง client เด็ดขาด ใช้เฉพาะใน Server Action)

## สร้างบัญชีเจ้าของคนแรก

ระบบไม่มีหน้า "สมัครสมาชิก" สาธารณะ (ตั้งใจ — ฟิตเนสไม่ควรให้ใครก็ได้สมัครเป็นเจ้าของ) บัญชีแรกต้องสร้างผ่าน
Supabase Studio ครั้งเดียว หลังจากนั้นเจ้าของจะเชิญพนักงาน/เทรนเนอร์ต่อได้เองในหน้า **ทีมงาน** และเชิญลูกค้าได้ในหน้า **สมาชิก**

1. **SQL Editor** รันเพื่อสร้างสาขาแรก:
   ```sql
   insert into public.branches (name) values ('สาขาทองหล่อ') returning id;
   ```
   จด `id` ที่ได้ไว้ (เป็น UUID)
2. ไปที่ **Authentication → Users → Add user → Create new user**
   - กรอกอีเมล/รหัสผ่าน แล้วติ๊ก **Auto Confirm User**
   - ในช่อง **User Metadata (raw)** ใส่ (แทน `<branch-id>` ด้วย UUID จากข้อ 1):
     ```json
     { "role": "owner", "full_name": "ชื่อเจ้าของ", "branch_id": "<branch-id>" }
     ```
3. Trigger `handle_new_user` จะสร้างแถวใน `profiles` ให้อัตโนมัติ — ล็อกอินด้วยอีเมล/รหัสผ่านนี้ที่ `/login`
   จะเข้าสู่แดชบอร์ดเจ้าของทันที

### แพ็กเกจ วันหมดอายุ เช็กอินด้วยการสแกน และตารางเทรนเนอร์

ต้องรันไฟล์ `supabase/memberships.sql` ใน Supabase → SQL Editor หนึ่งครั้งก่อน (รันซ้ำได้ ข้อมูลเดิมไม่หาย)
ถ้ายังไม่รัน หน้าที่เกี่ยวข้องจะขึ้นข้อความบอกให้รัน

- **แพ็กเกจ** (`/owner/packages`): เจ้าของสร้างแพ็กเกจสมาชิก (เดือน แถมเดือน แถมวัน) และแพ็กเกจ PT (ชั่วโมง แถมชั่วโมง) พร้อมราคา
  แพ็กเกจที่เลิกขายให้กดซ่อน ประวัติการขายเดิมไม่เปลี่ยน
- **บันทึกการขาย** (`/owner/members/รหัส` หรือค้นหาลูกค้าจากเมนูการขาย): มีสองแบบ
  สมาชิกรายเดือนเลือกจากแพ็กเกจ ระบบคิดวันหมดอายุให้และแก้ได้ก่อนบันทึก การต่ออายุเริ่มต่อจากวันหมดเดิม
  PT กรอกเองทุกครั้ง: ชั่วโมงที่ซื้อ ชั่วโมงแถม ราคาต่อชั่วโมงหรือยอดรวม เทรนเนอร์ที่เทรนให้ และผู้ขาย ไม่ต้องสร้างแพ็กเกจ PT ก่อน
  ทุกการขายต้องระบุผู้ขาย หน้าการขายสรุปยอดของผู้ขายแต่ละคนรายเดือนสำหรับคิดค่าคอม
  ชั่วโมง PT เพิ่มให้ลูกค้าทันที แก้วันหมดอายุภายหลังได้ (ใช้เมื่อพักสมาชิก) เจ้าของลบรายการที่ลงผิดได้
- **การขาย** (`/owner/billing`): รายการขายล่าสุดและยอดเดือนนี้ รายงานรายได้ใช้ข้อมูลชุดเดียวกัน
- **ลูกค้าเช็กอินเอง** (`/checkin`): พิมพ์ป้าย QR จากหน้าเช็กอิน → "ป้าย QR ให้ลูกค้าสแกนเอง" ลูกค้าสแกน กรอกเบอร์โทรที่ลงทะเบียนไว้ แล้วเห็นเวลาเข้า
  วันที่เหลือ ชั่วโมง PT ที่เหลือ และโปรโมชั่น ลูกค้ากดปุ่มเดียวว่าวันนี้มาเล่นเวท คาร์ดิโอ หรือเข้าคลาส ซึ่งเป็นการเช็กอินไปในตัว
  มือถือเครื่องเดิมจะจำเบอร์ไว้ ครั้งต่อไปสแกนแล้วกดปุ่มกิจกรรมได้เลยโดยไม่ต้องกรอกเบอร์ (มีปุ่ม "ใช้เบอร์อื่น" ถ้าใช้เครื่องร่วมกัน)
  ต้องมีสมาชิกที่ยังไม่หมดอายุเท่านั้นจึงเช็กอินได้ สมาชิกกับ PT ขายแยกกัน มีชั่วโมง PT เหลืออย่างเดียวเข้าไม่ได้
  สมาชิกที่หมดอายุ อยู่ระหว่างพัก หรือไม่มีแพ็กเกจสมาชิก สแกนแล้วเช็กอินไม่ได้ พนักงานยังเช็กอินให้เองได้จากหน้าเช็กอิน
  ทุกครั้งที่มีคนสแกน หลังบ้านของพนักงานและเจ้าของจะมีการ์ดเด้งขึ้นมุมจอทุกหน้า พร้อมเสียงเตือน เพื่อดูว่าคนที่สแกนอยู่หน้าเคาน์เตอร์จริง
  การ์ดสีแดงคือสแกนแล้วไม่ผ่าน และหน้าเช็กอินมีรายการสแกนไม่ผ่านของวันนี้
  หน้าเช็กอินของพนักงานแสดงจำนวนคนในยิมตอนนี้แยกตามกิจกรรม สแกนซ้ำใน 3 ชั่วโมงไม่นับเพิ่ม ไม่มีเช็กเอาต์ หน้า "ตอนนี้คนเยอะไหม" นับจากเช็กอิน 90 นาทีล่าสุด
  ถ้าป้ายหลุดออกไปนอกยิม เจ้าของกด "สร้างรหัสใหม่" แล้วพิมพ์ป้ายใหม่ได้
- **โปรโมชั่น** (อยู่ในหน้าแพ็กเกจ): ตั้งให้แสดงกับสมาชิกที่ใกล้หมดอายุ (ค่าเริ่มต้น 7 วัน) คนที่ชั่วโมง PT ใกล้หมด หรือทุกคน
- **ตารางเทรนเนอร์**: เทรนเนอร์ลงตารางของตัวเองทุกเช้าที่ `/trainer/schedule` (เทรนลูกค้า เทสต์ลูกค้า ว่าง ไม่อยู่ รายชั่วโมง 06:00 ถึง 22:00)
  ผู้จัดการดูทั้งทีมที่ `/owner/trainer-schedule` เห็นว่าใครว่างตอนนี้และใครยังไม่ลงตาราง
- **ลูกค้า PT ของเทรนเนอร์** (`/owner/trainer-clients`): ลูกค้าในมือของเทรนเนอร์แต่ละคน ใครใกล้หมดหรือหมดชั่วโมงแล้ว และวันนี้ติดลูกค้ากี่โมง
  ว่างกี่โมง ตารางเต็มหรือยัง ระบุเทรนเนอร์ที่ดูแลได้ตอนขายแพ็กเกจ PT หรือในหน้าของสมาชิก
- **หน้าขาย** (`/owner/sell`): หน้าเดียวสำหรับเซลล์ เลือกลูกค้าเดิมหรือเพิ่มลูกค้าใหม่ ขายสมาชิกรายเดือน ชั่วโมง PT หรือทั้งสองอย่าง
  เลือกเทรนเนอร์ที่เทรนให้ ผู้ขาย และวิธีชำระ แล้วบันทึกครั้งเดียว
- **แจ้งเตือนบนหน้าภาพรวม**: สมาชิกที่จะหมดอายุ ลูกค้า PT ใกล้หมดแยกตามเทรนเนอร์ ลูกค้า PT ที่ยังไม่ระบุเทรนเนอร์ เทรนเนอร์ที่ยังไม่ลงตาราง และคนที่ตารางเต็ม
- **ใหม่หรือซื้อซ้ำ**: ระบบแยกให้เองจากประวัติการซื้อ และแสดงยอดแยกกันในหน้าการขาย
- ยังไม่ได้ทำ: เช็กอินและแจ้งเตือนผ่าน LINE ต้องมี LINE Official Account และตั้งค่า LINE Login กับ Messaging API ก่อน ดู `docs/backlog.md`

### บัญชีทีมงานแบบไอดีและรหัสผ่าน

- เจ้าของสร้างบัญชีพนักงานและเทรนเนอร์ได้เองที่เมนู **ทีมงาน** ด้วยไอดีและรหัสผ่าน ไม่ต้องใช้อีเมล สร้างทีละคนหรือหลายคนพร้อมกัน
  และตั้งรหัสผ่านใหม่ให้ได้จากหน้าเดียวกัน
- ทีมงานเข้าระบบที่ `/login` ด้วยไอดีนั้น (ช่องเดียวกันรับได้ทั้งไอดีและอีเมล) หน้าเว็บสาธารณะไม่มีลิงก์ไปหน้า login
- ไอดีถูกเก็บเป็นอีเมลบนโดเมนสมมติ `staff.s365fitness.com` (ดู `src/lib/staff-login.ts`) ไม่มีการส่งอีเมลไปที่อยู่นี้
  บัญชีแบบไอดีจึงกู้รหัสผ่านทางอีเมลไม่ได้ ต้องให้เจ้าของตั้งใหม่ให้
- ต้องมีค่า `SUPABASE_SERVICE_ROLE_KEY` ที่ถูกต้องใน Vercel ถ้าไม่ถูก หน้าทีมงานจะขึ้นกล่องแดงบอก

### ตั้งรหัสผ่านและลืมรหัสผ่าน

- อีเมลเชิญ (พนักงาน เทรนเนอร์ ลูกค้า) พาไปหน้า `/reset-password` เพื่อตั้งรหัสผ่านครั้งแรก แล้วเข้าหน้าของบทบาทตัวเองทันที
- หน้า `/login` มีลิงก์ "ลืมรหัสผ่าน" ไปที่ `/forgot-password` ระบบส่งลิงก์ตั้งรหัสผ่านใหม่ทางอีเมล
- ลิงก์ในอีเมลใช้ที่อยู่เว็บที่คนกดส่งกำลังเปิดอยู่ ต้องเพิ่มที่อยู่นั้นใน Supabase → Authentication → URL Configuration → Redirect URLs
  (เช่น `https://your-domain.com/**`) และตั้ง Site URL เป็นโดเมนจริง ถ้ายังไม่ได้เพิ่ม Supabase จะพาไปหน้าแรกของ Site URL แทน
  ซึ่งเว็บจะส่งต่อไปหน้า `/reset-password` ให้เอง

## Deploy ขึ้น production

แนะนำ **Vercel** เพราะเป็นผู้พัฒนา Next.js เอง รองรับ Server Actions / Middleware ที่โปรเจกต์นี้ใช้แบบไม่ต้องตั้งค่าเพิ่ม
(ทางเลือกอื่นที่ใช้ได้เหมือนกัน: Netlify, Cloudflare Pages ที่รองรับ Next.js runtime, หรือ self-host ด้วย `next start` บน VPS/Docker)

1. Push โค้ดขึ้น GitHub แล้วไปที่ [vercel.com/new](https://vercel.com/new) เลือก repo นี้
2. ตั้งค่า **Environment Variables** ใน Vercel project settings ให้ตรงกับ `.env.local` (3 ตัวแปรเดียวกับข้างบน)
   - `SUPABASE_SERVICE_ROLE_KEY` ตั้งเฉพาะใน environment ของ Vercel เท่านั้น (Production/Preview) — เป็นความลับ ห้าม commit
3. Deploy แล้วนำโดเมนที่ได้ (หรือโดเมนของคุณเองที่ผูกไว้) กลับไปอัปเดตที่ Supabase → Authentication →
   URL Configuration (Site URL + Redirect URLs) ตามขั้นตอนที่ 4 ด้านบน มิฉะนั้นลิงก์เชิญผู้ใช้จะพาไป localhost
4. Supabase ฝั่ง production แนะนำให้ตั้งค่า **Custom SMTP** (Authentication → Emails → SMTP Settings) แทนอีเมล
   ทดสอบของ Supabase เอง เพราะมี rate limit ต่ำมาก ใช้จริงกับลูกค้า/พนักงานจำนวนมากไม่พอ (ใช้ Resend, Postmark, SES ก็ได้)
5. เปิด **Point-in-time Recovery / Daily Backups** ใน Supabase (Settings → Add-ons) เพราะเป็นข้อมูลธุรกิจจริง

## สถาปัตยกรรมสิทธิ์การใช้งาน

- **ทุกตารางบังคับด้วย Row Level Security (RLS)** ที่ Postgres โดยตรง — ต่อให้ผู้ใช้เปิด devtools ยิง request ตรงไป
  Supabase API ก็ยังถูกกรองสิทธิ์เหมือนเดิม ไม่ใช่กันแค่ที่หน้าเว็บ
- **src/proxy.ts** กันไม่ให้เทรนเนอร์/ลูกค้าเข้าถึง URL ของกลุ่มอื่นได้แม้พิมพ์ตรงๆ (เช่น เทรนเนอร์พิมพ์ `/owner` จะถูกเด้งกลับ)
- **เซสชัน PT แยกจอจริงตามที่ต้องการ**:
  - เทรนเนอร์ (`/trainer/pt-sessions`) เห็น **เฉพาะปุ่ม "บันทึกเซสชัน"** — บันทึกแล้วสถานะเป็น `pending` เสมอ
    (RLS policy `pt_trainer_insert` บังคับ status ต้องเป็น pending และ trainer_id ต้องเป็นตัวเอง)
  - ลูกค้า (`/member/pt-sessions`) เห็น **เฉพาะปุ่ม "ยืนยัน" / "ไม่ได้ใช้บริการ"** — เทรนเนอร์แก้สถานะเองไม่ได้เลย
  - เมื่อลูกค้ากด "ยืนยัน" ฐานข้อมูลจะตัดชั่วโมง PT ให้อัตโนมัติผ่าน DB trigger (`handle_pt_session_approved`)
    ไม่ได้ตัดจากฝั่งแอป — กันกรณี logic ฝั่ง client ผิดพลาดหรือถูกแก้ไข
  - ถ้าลูกค้ากด "ไม่ได้ใช้บริการ" สถานะเป็น `disputed` แสดงในแดชบอร์ดเจ้าของ/พนักงาน ให้ตัดสินใจอีกที
- บัญชีเข้าสู่ระบบสร้างผ่าน Supabase Auth Invite เท่านั้น (ไม่มีหน้า public signup) — เจ้าของเชิญพนักงาน/เทรนเนอร์
  จากหน้า "ทีมงาน", พนักงานเชิญลูกค้าให้มีบัญชีจากหน้า "สมาชิก" (ปุ่ม "สร้างบัญชี")

## ข้อจำกัดที่ตั้งใจลดความซับซ้อน

โปรเจกต์นี้ปรับจาก mockup ให้ทำงานได้จริงโดยยังคงหน้าตา/สี/โครงสร้างเดิมไว้ทั้งหมด แต่มีจุดที่ตัดความซับซ้อนออก
เพื่อให้ส่งมอบระบบที่ทำงานถูกต้องปลอดภัยได้ทันเวลา — ควรรู้ไว้ก่อนใช้งานจริง:

- **1 บัญชีพนักงาน/เจ้าของ ผูกกับ 1 สาขา** ตัว dropdown สลับสาขาในดีไซน์ต้นแบบจึงถูกทำเป็นป้ายชื่อสาขาแบบ read-only
  แทน ถ้าต้องการให้เจ้าของคนเดียวบริหารได้หลายสาขาพร้อมกันจริง ต้องเพิ่มตาราง `branch_memberships` และปรับ RLS
  policy ที่ใช้ `current_branch()` ให้รองรับหลายสาขาต่อ 1 คน (เป็นงานต่อยอดที่ทำได้ไม่ยาก โครงสร้างตารางรองรับอยู่แล้ว)
- **รายงานรายได้** อิงจากตาราง `payments` ที่บันทึกทุกครั้งที่กด "บันทึกจ่ายแล้ว" เท่านั้น (ไม่มีระบบตัดบัตรเครดิต/
  พร้อมเพย์อัตโนมัติ) ถ้าต้องการรับชำระเงินจริงผ่านเว็บ แนะนำต่อ Omise หรือ Stripe แล้วให้ webhook เรียก markPaid ให้
- **ไม่มีการแจ้งเตือนแบบ real-time (push/SMS/LINE)** ในเวอร์ชันนี้ ข้อมูลอัปเดตเมื่อโหลดหน้าใหม่/กดปุ่ม
  (ต่อยอดด้วย Supabase Realtime subscriptions ได้ในอนาคตถ้าต้องการให้หน้าจอเช็คอินอัปเดตสดโดยไม่ต้อง refresh)
